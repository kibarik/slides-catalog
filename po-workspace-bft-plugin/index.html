Два режима работы с требованиями

/BFT-FAST

Зафиксировать сказанное

/BFT-DEEP

Проверить в контексте бизнеса

Связанные функции, прошлые решения, ограничения и вопросы по доступным источникам.

15–30 минут

Ориентир автора для исследования

Это время работы агента. Проверка человеком и согласование требуют отдельного времени.

Роли Fast и Deep подтверждены README. Время предоставлено автором и зависит от объёма материалов, модели и доступности источников.

Сам Fast не читает внешние системы. Отдельная фоновая разведка bft-recon может искать связанные материалы.

Как работает /bft-fast

  1. Клонируйте репозиторий и установите навык bft-writer.
  2. Добавьте транскрибацию звонка и полезный контекст.
  3. Запустите /bft-fast <источник> <эпик> --no-deep.
  4. Откройте HTML. Проверьте требования и оставьте комментарии.
  5. Верните промпт с правками агенту и проверьте новую версию.
  6. После проверки запустите /bft-deliver <эпик>
    для публикации в Confluence и JIRA.
ПРОМПТ

Собери БФТ по транскрибации встречи. Сохрани цитаты-источники. Неизвестное пометь для уточнения. Подготовь HTML для ревью.

Команды и HTML-ревью: README навыка. Флаг --no-deep позволяет пройти Deep отдельным шагом демонстрации.

Pipeline /bft-deep

01 / SETUP + SEED

Проверить вход

Доступность источников и конфигурацию. Прочитать Fast, зафиксировать исходную шапку.

02 / CONTEXT

Поднять контекст

Индекс, вики, трекер, Git и прошлые артефакты. Каждую находку проверить в первоисточнике.

03 / AUDIT

Выявить пробелы

Противоречия, исключения, границы, термины и риски. Вопросы — в диалог с руководителем.

04 / ENRICH

Углубить требования

Ценность для бизнеса, «что если» в приёмке и явные границы доработки.

05 / DRAFT + VERIFY

Собрать и проверить

11 разделов. Типизация, источники и цитаты, валидация и ревью свежим агентом.

06 / EMIT

Сохранить результат

Полный БФТ и HTML в отдельных файлах. Исходный Fast сохраняется без перезаписи.

Контроль руководителяВ интерактивном режиме — пауза на вопросах. В фоне — пометки [УТОЧНИТЬ]. Существующая wiki-страница обновляется после превью и согласия; новую создаёт /bft-deliver.

Схема сокращает стадии 0–11 из оригинальной оркестрации Deep. Проверки источников: environment_setup.

Недоступные источники получают UNAVAILABLE. В интерактивной ветке продолжение без них согласовывается. Перед записью запускаются проверки соответствия источникам и шаблону. Deep не создаёт страницу и не пишет в трекер.

Тот же БФТ после Deep

Учебный результат на вымышленных источниках: 11 разделов, приёмка, зависимости, риски и ссылки на основания.

Демонстрационный документ продолжает тот же вымышленный пример «Бронирование переговорной». Сохранена шапка Fast, исходные ID перенесены в типизированные разделы. Добавления опираются на явно обозначенные вымышленные источники Д-01–Д-03.

Это учебная иллюстрация результата, а не отчёт о запуске Deep по реальным системам. HTML создан штатным экспортёром навыка.
